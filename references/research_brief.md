我核对了文件夹里的 **13 篇论文**，并补查了与候选改进方向最接近的新工作。按你目前的条件——**纯仿真、单张 24GB GPU**——我更建议研究：

**“动作条件下的证据可恢复性感知记忆”：机器人应该优先保存哪些以后无法重新看到的证据，以及何时值得重新观察。**

这个方向能直接切入 EventVLA 的记忆淘汰问题，但新颖性目前只能算**有待验证**：简单的“长短期记忆”“记忆更新”“遗忘成本”都已有工作，必须把问题限定得更具体。

下面先总结论文，再给出可以落地的方案。

**这 13 篇论文分别解决了什么，还有什么没解决。** 表中“原文”表示作者明确讨论或实验展示的问题；“分析”表示我根据方法设计提出的待验证判断。

这些论文不能直接按各自报告的成功率排高低：主干模型、训练数据、任务、历史输入和评测方式不同。对你最有价值的阅读顺序是 **EventVLA → SimpleMemVLA → KEMO / MemER → T²Mem → KeyRec**。

**之前提到的“短期流式上下文＋长期关键事件记忆”，现在可以明确说：作为架构概念，已有很多相近工作，不能单独支撑创新。** KeyRec 就非常接近这个组合，MEM、StreamVLN 也覆盖不同形式的多尺度记忆。:codex-annotation{index="1"}

进一步查重还发现，下面这些方向也已经有人做：

| 看起来容易想到的改进 | 已有工作覆盖到哪里 |
|---|---|
| 旧事实失效后修订记忆，并撤销依赖它的结论 | **REMM** 已显式连接证据、事实和任务状态，支持撤销与修复。[论文](https://arxiv.org/abs/2610.12710) |
| 根据实际执行结果更新任务进度 | **AGM** 已通过物理证据验证子任务完成，再推进记忆中的进度指针。[论文](https://arxiv.org/abs/2608.29537) |
| 将记忆改成以物体为中心的状态 | **Embodied-SlotSSM** 已研究物体中心的记忆状态演化。[论文](https://ojs.aaai.org/index.php/AAAI/article/download/37337/41299) |
| 记忆不足时主动观察、探索或打开容器 | **ActiveArena** 已系统研究主动信息获取、记忆写入与容量；**Memory for Attention** 研究有限观察预算下应该重新检查哪些对象。[ActiveArena](https://arxiv.org/html/2609.24124) · [Memory for Attention](https://arxiv.org/html/2607.23797v1) |
| 保存那些遗忘后重新获取成本高的信息 | **OSL-MR** 已在语言智能体中将遗漏、重新获取和过时信息成本纳入有界记忆优化。[论文](https://arxiv.org/html/2606.10616v3) |

因此，“加不确定性”“加入主动回看”“考虑遗忘代价”这些表述都太宽，存在明显重复风险。

**我建议从 EventVLA 的一个具体薄弱点切入：它预测关键帧，但事件库满了之后仍使用 FIFO 淘汰。**

这不是凭空猜测：EventVLA 的附录明确描述了容量紧张或冗余帧过多时，早期关键证据会被过早淘汰。与此同时，它本身已经预测未来关键帧，所以“提前保存重要画面”也不能作为你的新贡献。[EventVLA 方法与消融](https://arxiv.org/html/2606.20092v3)

更具体的研究问题可以是：

> **当机器人动作会改变信息的可获得性时，如何在有限记忆中分配容量，使不可恢复证据得到保护，同时允许可恢复信息通过低成本观察重新获得？**

例如，同样都是“之前看到过的颜色”：

- 杯子背面的颜色：转动杯子还能看到。
- 盒子内部的颜色：需要移动障碍、重新开盒才能看到。
- 屏幕上已经消失的一次性颜色提示：无法通过当前场景恢复。
- 即将被覆盖或清除的标签：执行下一步动作后，获取机会会改变。

**关键区别在于：记忆价值随动作和环境状态变化，而不只取决于画面新颖程度、时间远近或当前相关性。**

可以暂用工作题目：

**《动作条件下的证据可恢复性感知记忆，用于长时程机器人操作》**

方法先控制在三个部分：

1. **保留 EventVLA 式稀疏事件记忆接口。**  
   先集中修改保存、替换策略，使用相同的视觉编码和动作执行器，便于判断收益来自哪里。

2. **学习“丢掉这条证据会造成多大损失”。**  
   输入当前观察、任务、候选记忆及拟执行动作，预测：未来是否仍需要它、还能否重新获得、恢复需要多少动作。可以将目标理解为：  
   **遗忘代价＝丢弃后允许重新观察的后续成本－保留后的后续成本。**  
   这个目标的概念有先例；值得研究的是其机器人动作条件化建模和训练方式。

3. **用仿真中的成对分支生成监督。**  
   从同一个仿真状态分别尝试“保留证据”“删除后继续”“删除后重新观察”，记录成功率和额外动作成本，训练轻量评分器。仿真真值只用于离线标签和诊断，测试时仍只接收机器人可观察的信息。

主动回看可以先采用所有方法共享的简单策略，先验证记忆淘汰是否有效；有明确收益后，再研究保存与回看的联合决策，避免一开始同时训练多个模块导致无法解释结果。

它与最近工作的差别需要这样表达：

- 对 **EventVLA**：研究动作条件下的证据替换与保护，而不是重新提出关键帧预测。
- 对 **OSL-MR**：研究物理动作如何改变信息的可恢复性，不能仅把语言记忆评分器换到机器人上。
- 对 **Memory for Attention / ActiveArena**：重点是有限存储下“保留还是重新获取”的取舍，以及动作导致获取机会消失的情况。

**截至本次检索，我尚未在核对的工作中看到对这一具体问题的完整覆盖，但不能据此保证没有同题论文。** 这个方向的创新性最终要靠上述差异和实验成立，不能靠新名称。

它主要针对几篇论文中的以下问题：

| 已有问题 | 计划验证的改进 |
|---|---|
| EventVLA 的 FIFO 可能过早淘汰早期证据 | 根据后续损失与可恢复性替换，而非仅按时间淘汰 |
| KEMO 的运动启发式不直接对应信息价值 | 用实际任务后果提供记忆价值监督 |
| MemER 未充分解决记忆不断增长后的删除 | 在明确容量约束下学习保留与删除 |
| KeyRec 的新颖性、覆盖率不直接等于控制收益 | 把额外观察动作与最终决策损失纳入评价 |

它**不直接解决** T²Mem 的跨帧交换推理，也不解决低层抓取精度；这些应作为单独失败类型统计。

**单张 24GB 的实现应从小主干、轻量模块开始。**

- 使用 SmolVLA 规模的模型作为第一版执行器，先适配基础操作，再固定它比较记忆方法。Hugging Face 的官方硬件指南将 SmolVLA 列入 24GB 可用范围，但增加历史输入后的实际显存仍需测量。[官方硬件指南](https://huggingface.co/docs/lerobot/main/en/hardware_guide)
- 冻结视觉编码器，离线提取训练特征；先训练小型记忆评分器和必要的时间融合模块。
- 先采用 4～8 条历史证据、小批量、梯度累积。需要验证历史接口，不能假设 SmolVLA 可以直接替换 EventVLA 主干。
- 仿真数据生成与模型训练分时运行；第一轮不引入视频生成世界模型。

**实验设计比再加一个模块更重要。** 第一轮建议只做三类配对任务：

| 配对条件 | 要检验什么 |
|---|---|
| 相同线索，可再次观察 / 一次性消失 | 方法是否识别信息不可恢复性 |
| 相同线索，低成本 / 高成本重新观察 | 是否学到保存与回看的成本取舍 |
| 相同场景，不同操作使线索保留 / 被覆盖或清除 | 是否真正利用动作条件，而不是死记任务类别 |

先做 2～3 个任务原型，成立后扩展到不同物体、不同布局和未见过的恢复成本；同时保留原有标准任务，检查一般能力是否下降。

至少需要以下对照，且尽量共享主干、训练数据和执行器：

1. 最近窗口、均匀采样。
2. EventVLA 式关键帧预测＋FIFO。
3. 相关性／新颖性评分淘汰。
4. **手工规则：优先保存不可恢复证据。**
5. 去掉动作输入、去掉恢复成本、去掉成对分支监督的消融。
6. **完整视频存档＋检索，以及更长原生视频上下文。**

第 4、6 项尤其重要。仅超过 FIFO 不足以说明值得发论文；如果简单规则就一样好，学习模块的价值不足。如果完整视频放在 CPU／磁盘上再检索，在同样延迟预算下就能解决问题，就不能人为限制历史来制造优势。

报告最终成功率之外，还应报告：**决策时关键证据是否可用、目标选择准确率、重新观察次数、总执行步数、推理延迟、GPU 与外部存储占用**。记忆容量和实际读取 token 数也应分开统计。

我建议把第一阶段的目标定得很明确：**证明在相同预算下，“动作导致的可恢复性变化”能解释现有记忆方法的失败，并且学习方法能够超过强规则和完整存档检索基线。** 如果这点成立，再扩展成完整论文；如果不成立，应尽早换题，而不是继续堆模块。
