# 保守执行与效果约束（2026-10-16）

用户要求：服务器不稳定，实验配置应保守，允许更慢，但不能以降低实验质量或模型效果换稳定。当前仍按用户要求暂停，本次只保存配置和代码，不启动实验或排队任务。

## 已接入的默认运行配置

配置在 `configs/conservative_execution.json`，已接入下一步使用的 `run_native_parent_collection.py` 和 `run_native_slot_probe.py`。历史实验入口保持原样，不能假定它们也应用了新配置。

- 保持单 GPU、单仿真 worker、项目互斥锁；每次仿真任务和独立 GPU 回放之前休息 60 秒。休息发生在仿真进程之间，不推进仿真时间，不消耗模型随机数。
- 每 5 秒采样资源并落盘；连续两次异常则结束本 runner 创建的进程，保存已有结果，不自动反复重试或在重启后自启动。
- 采用本项目保守停止阈值：GPU 温度 75°C、CPU 温度 85°C、主机可用内存至少 32 GiB、GPU 剩余显存至少 8 GiB。这是实验调度选择，不是硬件厂商的故障判定标准。
- 等待前置批次时检查暂停状态和 boot ID，避免等待重启前残留的 evaluating 状态。
- 每次运行把执行配置及其源文件哈希写入快照；实验条件、未完成样本、基础设施中断和实际任务失败分别记录。

本次不设置系统功耗上限，不改驱动、时钟、CPU 线程数或模型数值路径。单次模型推理和渲染的峰值负载没有因此降低；主要改变连续运行节奏和停止时机。软件监测不能保证阻止驱动、固件或硬件导致的整机锁死，重启原因仍未确定。

## 保持结果可比

不修改冻结权重、推理精度、图像分辨率、事件容量的研究设定、随机数协议、仿真步长、动作执行方式、任务预算或样本名单。新入口只是改变任务之间的实际等待时间和资源守卫；这不会主动削减研究预算，失败或中断也不会伪装成已完成。

恢复执行时，先对已验证父状态运行原生保留基线，核验实际输入、动作及最终物理状态哈希。若出现不一致，先排查并保留差异，不宣称保守配置已保持效果。通过小规模真实闭环验收后再扩展长批次。本次只完成 CPU 测试，尚未在 GPU 上验证这些运行节奏变更。

未来正式训练优先降低数据加载并发、延长保存/检查间隔之间的休息并保留完整训练预算。若需要减小 microbatch，应同时保持等效 batch、优化器更新次数和学习率调度，并做训练对照验证；不把梯度累积自动当作数值完全等价，也不擅自减少训练轮数、样本量或精度。
