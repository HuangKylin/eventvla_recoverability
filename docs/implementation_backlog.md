# 按依赖顺序实施的任务清单

最新追加（2026-10-15）：T3 物理动作配对已完成 48 次独立运行和 32 个 K/R 标签；步骤 13 已进入机制原型训练，产生 60,321 参数评分器与去动作输入的消融权重。真实 EventVLA 的 5 个分支完成 826 个动作、17 次输入审计，重复轨迹一致，但指定盖子的控制验收为 0/5。当前关键依赖是步骤 08 的新任务控制适配，不是继续增加简单颜色诊断数量。正式 T2、完整 VLA 评分器训练和跨布局验证仍未完成；第一研究目标尚未达成。见 `action_stage_progress.md`。

既有基础：环境资产、原任务两回合闭环、固定控制器下的新进程重建回放、独立线索诊断及 K/D/R 采集入口均已完成。前一轮的 39 项测试及诊断范围记录在 `m1_progress.md`；最新状态以本文首段和 `implementation_status.md` 为准。

| 12 | 冻结协议中的步数/耗时尺度、延迟约束、分组划分和统计方案 | 将 JSON 状态改为 frozen，并记录生效版本；不得回看测试集调参 |

| 14 | 接入闭环，补采必要的训练分布状态，做三项消融 | 所有额外前向、缓存和回看成本计入；禁止隐形历史泄漏 |
| 15 | 按预定样本量运行主预算/三种子/泛化评测 | 按父场景族统计，逐种子报告，不用帧数扩充样本量 |
| 16 | 完成资源曲线、失败分析和 G2～G4 判断 | 明确成功率收益、效率收益或否定结果；只在证据成立时扩展论文 |

优先做的工程检查：

- 删除证据后，对应图像、语义特征和 KV 状态是否真正不可被有界策略访问。
- 相同状态复制后，不采取干预时两个分支是否给出一致的观测与动作。
- 父场景、配对条件、候选证据及兄弟分支是否全部处于同一数据划分。
- 原始 oracle 字段、任务答案和未来状态是否只存在于评测/标签进程。
- 检索和新方法是否共享相同的实际输入权限，并完整计入额外操作成本。

已测试选择器零容量、未来帧读取隔离、上游 FIFO 一致性、分支配对/分组、诊断控制器的删除语义及观察白名单。真实物理接触回放、物理触发机制和 VLA 已知删除帧的实际输入审计已验证；这不等于验证任意语义信息均不可推断。正式强检索对照、连续在线预算及完整新任务闭环仍未完成。过去单线索诊断不用于训练；本轮训练使用单独登记的动作配对机制先导数据，不宣称通过正式 G2/G3。
