# 第一阶段实施方案：动作条件下的证据可恢复性感知记忆

版本：2026-10-14，v0.1。状态：实施前方案；没有实验结果。依据：用户指定的《论文总结与改进方向.md》，原文保存在 `references/research_brief.md`。以下任务名称、模型结构、实验规模和验收阈值均为本项目的拟议设计。

实施更新：本方案保留最初研究设计；已完成的环境、资产和原任务首轮验证另记于 `implementation_status.md`，不将冒烟结果混作研究结论。实际检查点容量为 5 条事件图像，另有 4 个时间锚点 × 3 个视角；后续预算比较须计入这些共享输入与缓存。

## 1. 第一目标与本阶段交付

原文的第一阶段目标是：

> 证明在相同预算下，“动作导致的可恢复性变化”能解释现有记忆方法的失败，并且学习方法能够超过强规则和完整存档检索基线。

把“证明”落实为三个允许被实验否定的问题：

| 问题 | 需要的证据 | 不足以支持结论的结果 |
|---|---|---|
| H1：失败确实来自证据丢失及其可恢复性 | 同一初始状态下干预保留/删除证据；恢复机会或成本改变时，性能差异随之改变 | 只展示 FIFO 失败视频；失败主要来自抓取或动作模型不会执行任务 |
| H2：动作条件有独立价值 | 当前视觉、任务和历史相同，仅改变拟执行动作；完整模型超过去动作模型及动作知情强规则 | 只凭任务 ID、颜色、固定时间步就能判断“不可恢复” |
| H3：收益能经受完整存档对照 | 在公开、可复现的资源约束下，比较成功率与实际延迟、存储成本 | 只赢 FIFO；人为不给检索方法 CPU/磁盘；把效率收益说成成功率更高 |

本阶段交付应包含：三个配对任务原型、一套可靠的分支采集器、可部署的强基线、轻量评分器、固定协议下的结果表和继续/停止判断。联合学习回看策略、世界模型和真机实验留待这些判断成立以后。

## 4. 三类任务：只改变关键因果因素

新任务采用独立名称与版本；它们是拟建诊断集，不能把分数当作官方 RoboTwin-Mem 分数。统一结构：**观察线索 → 插入干扰事件使容量承压 → 执行动作 → 延迟查询 → 必要时回看 → 最终选择/操作**。

第一轮用颜色与位置的配对信息，后续增加符号、顺序或细节信息。目标不是只做容易被一个文本摘要完全解决的“记住颜色”任务，因此完整存档基线也应包含紧凑结构化记录对照。

| 拟建任务 | 配对干预 | 主要检验 |
|---|---|---|
| T1 `revisit_or_erase_cue_v1` | 同一线索在离开视野后仍可通过开盖看到，或在明确可观察的清除动作后永久消失 | 物理不可恢复证据是否值得优先保存 |
| T2 `revisit_cost_v1` | 同一线索均可恢复，改变遮挡、距离及合法操作序列，形成低/中/高恢复成本 | 是否学到成本取舍；是否只会判可恢复/不可恢复 |
| T3 `action_changes_access_v1` | 同一状态、同一历史，下一段动作分别为可逆遮挡与不可逆清除；两种动作都属于合法任务流程 | 当前拟执行动作是否改变应保存的证据 |

主评测每个父场景先选两个条件组成一对；T2 先比较低/高成本，中间成本和更广的成本扫描另计回合，不混入后文的 600 回合预算。

T3 的动作必须发生在**淘汰决定之后**，否则模型可能仅从“已经消失的画面”推断，不需要动作输入。测试时不提供未来图像、分支结果或真值可恢复性。训练中应随机化动作与颜色、对象、布局的对应关系；测试保留新布局、新恢复成本及动作与线索的新组合，避免模型记住固定类别。

每个任务都明确“检查阶段”与“最终提交阶段”。回看在检查阶段合法，终止时间和失败条件对所有方法一致。保持线索数量、出现时长、干扰数和总时长尽量配对；避免用更长轨迹同时引入更多干扰，从而混淆恢复成本与记忆难度。

**物理恢复与历史检索分开统计。** 屏幕提示消失后，机器人可能无法从环境恢复，但完整存档仍可检索先前画面。新方法必须接受这个强对照，不能把“物理不可恢复”当作“任何方法都无法恢复”。

首先用带真值的脚本控制诊断任务是否可完成，再接入仅使用合法观察的公共控制器。前者只能用于任务正确性与上界，不能拿其成功率代替 VLA 闭环结果。原检查点在新任务上不会执行时，用相同演示数据统一适配所有方法的动作主干，再冻结比较；训练时混合不同记忆配置，减少主干偏向某一种缓存格式。

## 5. 公共接口与拟实现的轻量方法

主要比较只改变淘汰策略。所有有界事件库方法共享视觉编码器、动作模型、关键帧候选生成器、回看策略和输入预处理。第一轮固定主预算为 4 条历史图像证据，另测 2/8 条；当前图像另计，但所有方法摄像头数量与分辨率相同。

一次决策顺序拟定为：

1. 用当前观察、任务及现存记忆产生公共的暂定动作 `a_proposed`；它不是未来真实动作或专家动作。
2. 生成当前候选证据，评分器同时评价旧证据与新候选，决定是否接纳以及淘汰谁。
3. 必要时用更新后的记忆再生成一次动作；记录两次动作差异，并计入总推理开销。若采用双次前向，所有对照都使用同样的公共流程。
4. 执行动作并更新环境；达到公开触发条件时运行公共回看策略。

一条证据包含图像或允许的图像表示、时间戳、视角及对应动作摘要。额外特征和文本摘要同样算存储，删除图像后偷偷保留其可还原语义的 embedding、KV cache 或标签，会破坏有界记忆定义。日志只由评测进程访问，策略不能读取历史视频和真值文件。

评分器输入为当前观察特征、任务特征、候选证据特征、其余记忆摘要，以及可用的暂定动作特征。第一版用冻结编码器加小型 MLP/集合编码器，目标新增参数不超过约 5M。对动作序列做时序池化或小型编码；动作维度、步数从实际 adapter 读取，不把上游某配置的形状写死。

主输出直接预测删除候选证据的边际代价 `delta`，淘汰预测代价最小的一条；它可以选择不接纳新候选。辅助输出可预测未来需求、回看成功概率与恢复步数，但不强制用三者相乘，以免一个不准的概率压低所有评分。相似证据之间存在替代或互补，因此评分必须看到其他保留证据，不能只孤立评价单帧。

第一阶段的回看触发器采用固定规则，例如“到了指令要求的查询阶段，已有证据不足以达到校准后的置信阈值”；搜索顺序依据可观察的位置和动作记录。它不能直接读取真实目标或线索所在容器。所有方法在验证集上统一校准后冻结，回看耗时计入任务总成本。

## 6. 用成对仿真分支产生监督

对同一决策状态、同一候选证据和同一拟执行动作，运行三个分支：

| 分支 | 记忆操作 | 回看权限 | 用途 |
|---|---|---|---|
| K | 保留候选证据 | 公共回看规则可用 | 参考结果 |
| D | 删除候选证据 | 禁止回看 | 诊断遗忘本身的影响 |
| R | 删除候选证据 | 公共回看规则可用 | 学习实际可恢复时的删除代价 |

K/R 是主要训练配对，D 只帮助分解失败。单候选诊断中，其他记忆保持一致；这是测量边际代价的干预。最终容量实验中仍须恰当地选择替换项，不能用“多保留一帧”的诊断上界冒充同预算方法。

定义拟定的轨迹成本：

```text
J = 1[任务失败]
    + 0.10 × min(实际执行步数 / 公共步数上限, 1)
    + 0.02 × min(端到端计算耗时 / 公共耗时归一尺度, 1)

delta_i = E[J(R_i) - J(K_i)]
```

正值越大，证据越应保护。失败惩罚大于两个附加项的总和。步数上限和耗时尺度在先导实验中标定并冻结，不能用测试集调权重。报告原始成功率、步数与耗时，以及去成本项和权重敏感性，避免结论依赖某个加权分数。若耗时标签噪声过大，先只训练失败与步数项，把耗时留作评测，并记录协议修订。

分支配对需要恢复：物理对象位姿与速度、关节和驱动目标、任务阶段、计数器、随机数状态、控制器状态及策略记忆。先验证完整快照；不支持时采用“同 seed 重置＋回放相同动作前缀”，并用状态与观测误差检查是否真的恢复。只相同 seed 不足以认定同一状态。超出容差的配对作废并统计比例，不能混入标签。

训练/验证/测试按 **场景族与分支父状态** 分组，所有兄弟分支和对应动作配对必须处于同一划分。标签生成可以读取真值，模型输入只能来自经过白名单检查的 RGB、任务文本、本体状态、执行记录与当前合法记忆；task ID、oracle 字段、未来状态、答案路径均隔离。

第一版用 Huber 回归加候选间排序损失。先冻结编码器缓存特征，再训练评分器。新增任务执行器若曾适配，应在分支采集前固定。用最终评分器闭环运行后，可在训练场景补采一轮新访问状态，减少离线标签与新策略的分布差异；不能用测试场景补采。

## 7. 必须打得过的对照

| 对照 | 实现要求 |
|---|---|
| 最近窗口、均匀抽样 | 同等历史读取预算；与事件候选流不同的采样方法单列说明 |
| EventVLA 事件候选＋FIFO | 保持候选生成、阈值和动作模型一致，仅改变替换策略 |
| 相关性＋新颖性 | 用冻结特征计算任务相关性、重复度；在同一验证集调参 |
| 动作知情强规则 | 根据可观察的动作类型、对象状态与粗略恢复路径，优先保存即将丢失且仍有用的证据；不使用真实可恢复标签 |
| 完整事件存档＋检索 | 保存全部公共候选；查询利用任务、当前观察和暂定动作；检索后仍只读同样多的历史图像 |
| 完整观测存档＋检索 | 保存策略实际接收的全部观察，允许 CPU/磁盘、索引与重排；图像压缩、索引和读取成本全部记录 |
| 紧凑结构化记录＋检索 | 对简单颜色/顺序任务记录可观察语义，检验新方法是否仅靠较大的原始图像表示制造优势；摘要生成成本计入 |
| 更长原生历史上下文 | 改变读取规模后画资源—成功率曲线，不能把它与 4 帧设置说成同一读取预算 |
| 真值重要性/真值可恢复性 | 仅作诊断上界，图表明确标为使用特权信息，不进入可部署方法排名 |

新方法至少做三项消融：去拟执行动作、去恢复成本、去成对分支监督。去动作消融必须保留其他观测和参数规模；去监督可用相同结构学习简单事件重要性，避免把“额外数据更多”误说成“因果配对必需”。记录每种方法的训练数据、标签成本及调参预算。

检索方法不能只放一个弱相似度实现。先在验证集比较任务查询与动作条件查询、去冗余和合理重排，选最强有效版本后冻结。允许其复用已经计算的视觉特征，不能给它重复计算、给新方法免费缓存。

## 8. “相同预算”的可操作定义

把预算拆开报告，而不是只写“4 帧记忆”：

- **读取预算**：每次送入动作主干的历史图像数、实际视觉 token、文本 token；当前观察单列。
- **存储预算**：GPU 常驻/峰值显存、CPU 内存、磁盘字节、图像与索引、跨决策缓存；共享模型权重单列。
- **计算预算**：视觉编码、记忆更新、检索、重排、动作预测、必要的第二次前向与通信的总耗时；同时记录仿真物理执行步数。

做两张主表：

1. **有界事件库实验**：2/4/8 条容量，使用相同输入协议，比较各淘汰策略，检验动作条件与可恢复性的作用。
2. **完整存档竞争实验**：同一服务器、读取上限和任务步数上限，完整存档可用 CPU/磁盘。先测不加人为延迟截断的表现，再按事先冻结的实际应用延迟预算比较可行方法，并画成功率—延迟—存储曲线。

延迟预算由先导测量与任务需求确定，不能看到结果后专门设置在检索耗时之下。若静态任务允许无限等待，则延迟只是效率指标，不能随意将超时检索算失败。资源超限的结果标为该预算下不可行，同时展示原始成功率。

如果存档检索在合理资源下解决全部问题，那么“必须学习淘汰”的动机不成立。若新方法只节省存储或延迟，应将结论收窄到效率权衡，不能写成已经完成原定的成功率超越目标。

## 9. 数据规模、统计和运行成本

采用逐级投入，先排除任务和控制问题，再扩大训练。以下是工作量上限的起始建议，全部不是已运行结果。

| 阶段 | 初始规模 | 用途 |
|---|---|---|
| 冒烟 | 1～2 个原任务各 10 回合；新任务每种条件 5 回合 | 验证环境、加载、控制和日志 |
| 标签先导 | 每类任务 40 个父场景族，每族 2 个动作条件、每条件 1 个候选、3 个分支，共 720 次分支续跑 | 验证配对恢复、标签信噪比与基本现象 |
| 先导评测 | 每类任务 30 个配对场景，每场景 2 个条件，共 180 回合/方法 | 校准协议、选出有效基线；不作为最终测试 |
| 第一轮训练 | 每类任务 200 个训练场景族×2 个动作条件×最多 4 个候选×3 个分支，上限 14,400 次分支续跑 | 只在先导通过后生成；同一 K 分支满足条件时可复用，但保留对应关系 |
| 正式验证 | 每类任务另设 50 个场景族 | 调参和早停，不与训练/测试共享父状态 |
| 正式测试 | 每类任务另设 100 个配对场景×2 个条件，共 600 回合/方法/模型种子 | 主预算先跑主要方法，关键比较用 3 个训练种子 |

先在 4 条历史预算上跑 FIFO、强规则、两种完整存档、结构化记录和新方法。明显失败的控制管线先修正，不继续扩大评测。2/8 条预算、消融和长上下文在主结果有信息量后再展开，避免一开始铺满矩阵。

三个模型种子不等于三倍独立场景。使用相同配对场景跨方法比较，按父场景族做 bootstrap，并报告每个训练种子的结果及跨种子波动；正式显著性分析保留这种层级关系。初始 100 对/任务只是起点，不保证能识别 5 个百分点差异。按验证集方差预先做样本量估算，测试集不反复查看后决定何时停止。

每条轨迹记录：成功、目标选择正确性、决策时所需证据是否可访问、回看次数与成功率、执行步数、端到端 p50/p95 延迟、图像/token 数、GPU/CPU/磁盘占用和失败类型。报告中区分记忆丢失、信息已过时、检索未命中、推理错误、控制失败和超时。

先导后按实测估算费用：`总分支 GPU 时 ≈ 分支数 × 平均续跑秒数 / 3600`，另加评测、编码与训练时间。没有这些读数之前不承诺“几小时训完”。优先缓存冻结特征；评分器初次训练上限可设 10,000 步并以验证集早停，调整须记录。

## 10. 验收门槛与停止条件

以下阈值用于立项决策，先导阶段可合理修订并写入协议；正式测试前冻结。

| 门槛 | 建议验收 | 未通过时 |
|---|---|---|
| G0：系统可运行 | 原任务推理及渲染稳定；20 个连续回合无基础设施错误；配置、显存、耗时可复现 | 修环境与接口，不训练评分器 |
| G1：任务确实受记忆约束 | 足够历史的公共执行器在先导任务中达到约 90% 成功；至少两类任务的证据保护诊断比 FIFO 高约 10 个百分点 | 区分控制失败、候选漏写与淘汰失败；没有记忆瓶颈则停止当前构造 |
| G2：学习有额外价值 | 至少两类任务上，学习方法比最强可部署规则高约 5 个百分点，并有配对置信区间支持；未见布局/成本仍有效 | 查规则是否已解决问题；若如此，不继续堆复杂模块 |
| G3：完整存档仍不能消除贡献 | 在预先声明的共同资源约束内，成功率超过最强存档检索并有统计支持 | 若只做到成功率不劣于约 2 个百分点且延迟降低约 20%，只能转为效率论文假设；若存档全面更好，原目标未达成 |
| G4：动作条件不可替代 | 去动作消融在 T3 和未见动作组合上明确变差，且不是由未来信息泄漏产生 | 把结论退回一般价值记忆，重新评估与已有工作的重合 |

G1 中的真值证据保护是诊断上界；达到该差距不表示可部署方法已经有收益。所有百分比门槛都是建议的实际效应大小，不是对结果的保证。

## 11. 实施顺序与时间安排

按一人推进估计约 4～6 周；可用时间、依赖兼容和数据吞吐会改变工期。

| 阶段 | 预计投入 | 完成物 |
|---|---|---|
| M0：环境与原任务 | 2～4 天 | 固定版本、单卡入口、原任务冒烟报告、真实资源读数 |
| M1：任务与配对恢复 | 4～6 天 | 三类新任务、合法回看协议、状态恢复误差报告、720 次先导分支 |
| M2：强基线与预算 | 3～5 天 | FIFO/规则/存档/结构化记录，先导比较及冻结协议；先作一次继续判断 |
| M3：轻量评分器 | 4～6 天 | 分组数据、冻结特征、评分训练、动作与成本消融 |
| M4：闭环评测 | 5～8 天 | 三种子主表、泛化、资源曲线与失败归因；视统计功效调整预设样本量 |
| M5：研究结论 | 1～2 天 | 第一目标是否成立的证据包，或明确的停止/收窄结论 |

第一步具体做 M0，不先下载全部数据或完整复现 8 卡训练。先下载匹配检查点与必要资产，使用官方任务确认运行链路，再投入新任务开发。

## 12. 目录、接口与最终证据包

已创建目录；下列 Python 文件是拟实现的模块，还未存在：

```text
third_party/           固定版本的 EventVLA 与必要依赖源码

src/counterfactual/    状态恢复、分支执行、标签与有效性检查
src/evaluation/        成功判定、成本统计、失败归因

tests/                 状态恢复、分组隔离、删除语义、预算审计
configs/               本次协议草案及后续可执行配置

```

优先定义四个边界：`MemoryPolicy` 接收合法观察并返回保留项；`RecoveryPolicy` 只用可观察信息产生回看动作；`BranchRunner` 负责恢复与分支匹配；`EpisodeMetrics` 只读真值作评测，不向策略反传答案。具体函数签名在定位上游接口后确定。

最终证据包至少包含：冻结配置与版本、数据划分及哈希、各方法原始逐回合结果、按配对场景统计的差值与区间、动作条件消融图、成功率—成本曲线和失败案例。论文核心表述应落在**动作改变物理证据恢复机会时的存储决策及其训练证据**，而不是再次宣称发明长短期记忆、回看或遗忘代价。
