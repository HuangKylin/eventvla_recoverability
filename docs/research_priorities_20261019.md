## 现有原生任务初筛

以下是源码层面的风险判断，不是已运行这些任务的结论。存在紧凑表示不等于模型能从像素可靠提取它，更不等于已经训练出可部署控制器；必须把感知、表示和控制分开。

| 任务 | 源码依据 | 对当前论文假设的判断 |
|---|---|---|
| `cover_blocks_hard` / 现有独立颜色扩展 | 四槽位颜色；原生无重复，扩展独立采样 | 当前构造不再扩量；作为接口回归任务保留 |
| `pick_objects_in_order` | 三个盖子；四个类别中无放回取三个；前排是相同三物体的打乱顺序 | 不只是换成物体名称就能产生学习必要性；先纳入类别/位置表和排除推断；原样不准入 |
| `reproduce_route` | 四个垫子路线，后续物体复现已记录访问顺序 | 可用很短的访问序列表示；原样缺少动作条件下的恢复机会对照，不优先运行 |
| `put_back_block_hard`、`rearrange_blocks_hard` | 两行的首次左右访问，或首次移动的是两块中的哪块；后续按历史继续 | 关键历史可由少量状态表示；不能把长执行时间误当成高记忆容量压力 |
| `find_seal_and_seal_stamp` | 单个印章位于四盖之一，再执行取用盖章 | 主要隐藏身份是单个位置；原样不适合多证据容量取舍 |
| `observe_and_pickup` | 多类多实例物体；一个展示目标随后被墙遮挡；墙由观察计数触发 | 可复用视觉实例资产；但只有一个目标且遮挡非动作触发，原样同时缺少容量压力和 T3，不能直接升级成主任务 |

## 下一候选只保留一个准入问题

优先考察“多实例视觉证据，动作改变后续访问机会”的可行性，复用 `observe_and_pickup` 的实例资产与已有记忆接口。它目前只是候选，不是承诺能成立的新任务。暂不同时铺开路线、印章、交换物体等新实验。

先完成一份可被否定的任务说明，要求同时回答：

1. **真实信息需求**：后续查询需要哪些视觉细节？类别/位置表、实例特征索引和历史裁剪检索各保留什么？如果紧凑记录已足够，就结束该候选；不靠禁止强基线制造需求。
2. **动作配对**：同一决策前观察与历史，仅拟执行动作不同；恢复机会或可测物理成本改变。还必须有相同动作在不同可观察布局下产生不同最优保留项，排除固定动作 ID 映射。
3. **可恢复性**：把实际遮挡/搬移/访问路径与恢复过程写清楚；避免再用一个动作编号直接绑定“删除这个答案”的规则作为主证据。
4. **公平预算**：允许 CPU/磁盘完整存档，计入检索、编码、读取 token 和实际延迟；若几十条证据用廉价索引已够，就不能主张“必须学会遗忘”。效率收益与原成功率目标分开。
5. **公共执行器**：先检查原生能力与已有资产，禁止把低层操作适配无限加入记忆方法的前置任务。公共适配如确有必要，所有方法共享权重和感知权限。

**一次候选设计审查、至多一次针对性修订。** 若仍无法指出上述瓶颈及可检验的改进空间，停止当前构造路线，给出明确的研究范围调整建议，不再自动堆新任务或网络模块。此次数限制针对本轮路线收敛，不是实验统计样本数。

通过 P1 后才冻结小先导的场景名单、完整基线、预算和停止条件。小先导可以决定是否训练试验，不能提前宣称有论文创新；完整 G1 和正式比较另行验收。
