# 原生事件记忆依赖性对照（运行前固定）

研究阶段仍为第二步。本轮不采集 K/R 标签，不训练评分器，不估计完整任务成功率。

父状态使用 `20261015T092610Z_native_boundary_controls` 中已验证的两个 prepare 快照：seed 100000 的第 810 步，seed 100001 的第 808 步。四盖关闭、双手释放、原生动作块结束；当前三个视角没有积木可见像素。原生指令完整保留，目标是原生最终阶段第一个红色积木。每个种子仅运行三个分支，共六条闭环轨迹，单 GPU 顺序执行。

| 条件 | 事件图像 | 时间、置信度等元数据 | 时序锚点与当前观察 |
| --- | --- | --- | --- |
| keep | 原有四张 | 保留 | 保留 |
| drop_all | 全部移除 | 同步移除四条 | 保留 |
| mismatch | 另一种子四张真实检查图像，按事件顺序对应 | 保留接收方元数据 | 保留 |

错配供体预先固定为两个种子相互交换。100000 的原生红色目标为从左数第 3 个盖子，100001 为第 4 个。模型仅接收 RGB、机器人自身状态、原生指令和原接口事件字段；供体种子、真实槽位和分割图只供评价使用。错配保留图像形状、类型、字节数与数量；它更换了整幅历史观察，可能包含背景及姿态差异，不是只修改颜色像素的干预。供体事件均早于接收方分支时刻，也没有使用未来动作或评价结果选取供体。

三个分支均清空已执行的动作块缓存、前一动作、待提交事件及动作集成缓存；绝对动作模式下运行。每次推理均重置服务器缓存，并固定 `paired_seed=91000+timestep`。清空后 keep 必须与上一轮原生分支比较，检验缓存处理是否改变行为。

每条轨迹重放同一前缀，严格检查物理、当前观察、时序历史和原事件快照哈希。首次实际模型请求必须符合预注册图像哈希、锚点、事件时间、元数据和指令。删除/替换掉的旧图像哈希在后续请求中亦审计。共同保留的供体图像不计作删除泄漏。

评价沿用静止初始高度基准：连续 3 个物理 tick 抬高超过 4 cm，记为首次抬盖；同时抬多盖不能算单一正确选择。另记录原生实际揭盖区域命中、原生进度及失败。遇到首次错误抬盖、首次实际揭盖、原生失败或 300 个策略动作上限即结束。错配分支同时记录首次抬盖是否跟随供体红色位置。首次错误抬盖终止的分支不能声称后来一定揭开错误盖子或无法纠正。

解释限制：仅两个已选定父状态，是机制诊断；keep 2/2 不能当作普遍成功率。删除后的正确选择可能来自猜测或其它历史线索；错配行为改变若跟随供体目标，可以支持事件内容影响当前动作，但不能单独证明恢复成本评分器有优势。正式 K/R 还需共同非特权回看动作及配对恢复代价。
