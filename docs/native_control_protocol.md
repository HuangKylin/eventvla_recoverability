## 原生阳性对照

使用原始 `cover_blocks_hard`、原生唯一颜色排列、完整原生指令，从初始状态执行真实 EventVLA 动作。观察顺序由原生任务与模型执行产生；所有图像时间戳来自真实 `take_action_cnt`，关键帧由原客户端自动提交。保留原客户端首次动作块重规划默认设置。

预设两个种子：100000、100001。每条原生完整任务使用原生 1700 动作预算。策略权重冻结、严格加载；沿用本项目 SDPA、SAPIEN none/128 渲染兼容配置。每次模型请求重置服务端记忆并设置 `91000 + timestep` 随机种子。该设置与未包装的官方服务存在区别，所以这里只称本地原生任务控制，不称官方分数复现。

## 同一父状态的指令对照

在原生检查四个盖子结束、尚未完成第一次最终揭盖时保存：已执行的模型动作、客户端全部历史与缓存、物理状态及当前公开观察哈希。后续每个分支在新进程、新场景内重放同一动作前缀；物理与观察哈希必须完全相同，否则停止配对。

随后加载仅含本实验本地客户端状态的可信快照，并在每个分支同样清空旧动作块和待提交事件，不删除任何视觉证据。对照组为：

- `native`：保留完整原生指令。
- `position`：要求打开红块所在位置的盖子，使用上轮相同格式的位置短指令。
- `color`：使用原生示范中的 “Finally open the cover hiding the red block.”。
- `native_repeat`：重复完整指令分支，检查轨迹确定性。

目标盖子均为原生任务下一步要求的红块盖子。位置指令明确给出空间位置，因此不能与颜色指令比较记忆需求或信息预算；这里只测运动执行能力。仿真真值仅用于选择这个公开位置请求与评价，不作为模型额外状态输入。

原客户端在语言字符串改变时会调用 `reset()`，清空历史。本实验先更新 `task_description` 再调用 `step()`，刻意保持历史，以便只干预语言。该控制不能测试“模型能否听从任意相反目标”，因为各指令的目标一致。

继续执行最多 300 个真实模型动作。评价端只观察盖子物理抬升超过 4 cm 的首次事件，不改变颜色或场景。该成功指标与原生整段任务成功不同，分别报告。所有仿真进程串行运行于 GPU 1。

## 复现与审计

```bash
envs/tools/bin/python scripts/run_native_controls.py --gpu 1 --seeds 100000 100001
envs/tools/bin/python scripts/summarize_native_controls.py <运行目录>/status.json
```

`runs/*_native_controls/` 保存源码快照、作业参数、策略服务日志、分支日志、动作数组、原生前缀快照和图片。客户端快照含大量原生图像历史，仅保留在服务器；不得加载来源不明的 pickle 文件。

每次执行均记录实际请求的图像载荷和哈希，策略接口只收到 RGB、指令与机器人关节输入。运行时专家几何与规划入口由已有 tripwire 禁止。`reports/native_control_validation.json` 汇总物理/观察/历史一致性、重复轨迹、真实动作数及各组结果。结果应在控制实验完成后解读，不能预先认定已经定位失败原因。
