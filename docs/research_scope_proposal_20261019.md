# 候选结束后的研究范围调整提案

状态更新（2026-10-19）：用户在提案后要求继续，已按此范围开展可行性核查；不追认原目标完成。已实现读取合同并完成 CPU 输入审计，尚未启动新任务、模型推理或训练。最新约束见 `archive_readout_progress_20261019.md` 与 `archive_readout_protocol_v1.json`；下文保留提案内容。

## 为什么此时需要调整问题定义

原目标是在相同预算下，以动作导致的可恢复性变化解释记忆失败，并让学习淘汰优于强规则与完整存档检索。

已完成两个开发决策：

1. 现有简单颜色机制不值得扩大：强规则和紧凑记录已经解决已观察情况。
2. 多实例、动作遮挡的唯一候选已完成一次设计审查和一次修订审查。带公开观察编号的版本被几何规则和直接索引存档反例覆盖；改成视觉查询的版本尚未建立视觉检索难度及动作独立收益。后一项没有被真实机器人实验否定，但不足以批准当前高成本扩量路线。

因此不继续自动追加“更复杂任务”，也不把 GPU 空闲当成必须跑模型的理由。当前正式阶段仍是第二步，第一目标未达成。

## 推荐重新检验的假设

**允许所有方法保存同样的完整历史，在相同读取 token 和端到端计算预算下，拟执行动作是否能改善证据选择与回看决策？**

这一表述把存档作为公共基础设施，把可比较的方法放在证据读取和行为决策上。它不预设删除历史优于保存历史，也不把普通检索失败直接算成物理不可恢复。若进一步只得到效率收益，应按效率贡献报告，不能算作原成功率目标的完成。

具体可审查的实验合同如下，尚未执行：

- 所有方法接收相同已观察图像、任务文本、本体状态和同一个决策前动作提议；完整 CPU/磁盘存档与写入成本共同提供并计费。
- 共用视觉编码器、执行器、事件写入器、读取图像/token 上限与回看权限。
- 比较查询相关性检索、覆盖/时序规则、动作知情规则、学习查询检索、学习查询加动作检索。必须保留“学习但无动作”的对照，分离学习能力与动作条件的收益。
- 若要发起回看，必须说明历史信息缺失、过时或未涵盖所需视角的原因；先检查完整存档能否解决。同样的触发器和控制器适用于所有方法。
- 主结果同时记录正确决策、完整任务成功、实际操作步数、编码/查询/检索/推理耗时、CPU/GPU/磁盘开销。不能用纯向量搜索的毫秒数代替整个管线。
- 泛化划分按物体实例与布局，不以相同素材的复制条目增加独立样本量。
- 候选必须先找到一种实际失败模式：相同完整历史与读取预算下，查询检索/强动作规则确有不足，且不足可归因于动作相关的信息价值，而非模型不会抓取、错误索引或未适配指令。
- 没有这样的失败模式就停止，不先训练一个更大评分器寻找可汇报的差异。

上述是新的可检验问题，仍需重新查重和最小先导。现有审计没有证明其新颖性、必要性、性能优势或可发表性。下一轮若采用这一提案，应先更新第一阶段目标与验收标准，再冻结实验；不沿用旧实验名义宣称原路线成功。

## 保持原淘汰假设的条件

若坚持原主张，首先需要真实的存档限制或检索失败证据，包括约束来源、完整成本和强检索器，而不只是人为限定 GPU 中只能有几张图。现有 8～128 条低分辨率图像的 CPU 载荷测量不支持把外部存储本身当作主要瓶颈；该结论不外推无限视频、更高分辨率或冷盘传输。

当前不再为这个未建立的前提继续扩量颜色场景或修槽位接口。已有环境、权重、轨迹回放、输入审计和保守运行工具继续保留，可用于后续真正通过准入的研究。
